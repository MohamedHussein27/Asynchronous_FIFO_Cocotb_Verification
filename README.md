# Asynchronous FIFO Verification Using Cocotb & Verilog

## Overview

An **Asynchronous FIFO (First-In First-Out)** is a dual-clock buffer used to safely transfer data between different clock domains. It addresses **Clock Domain Crossing (CDC)** challenges using:

- **Gray-coded pointers**
- **Synchronization registers**
- **Robust FULL/EMPTY flag generation**

Asynchronous FIFOs are widely used in:

- **SoCs**
- **High-speed data pipelines**
- **DMA engines**
- **Communication interfaces**
- **Systems where modules run at unrelated clock rates**

This project verifies an asynchronous FIFO design using Python Cocotb verification methodology.

## Project Goal

Verify correctness and CDC safety of an asynchronous FIFO transferring data from a fast domain (**100 MHz**) to a slow domain (**40 MHz**).

Ensure reliable transfer of **9 bytes** without data loss.

**Validate:**

- FULL / EMPTY flags
- Pointer synchronization
- Simultaneous read/write behavior
- Random + directed transaction correctness

## Verification Approach

### Python Cocotb-Based Verification

A complete Python verification environment built using **cocotb**, including:

- **Driver**
- **Monitor**
- **Scoreboard**
- **Functional coverage** (cocotb-coverage)
- **Randomized transaction generator**

Simulation is run using **Icarus Verilog**, waveforms viewed in **GTKWave**.

This demonstrates modern verification practices compared to traditional HDL-only flows.

## Asynchronous FIFO Specifications

### General Characteristics

- Dual-clock architecture
- Gray-coded write/read pointers
- Pointer synchronization across domains
- FULL & EMPTY flag generation
- Supports concurrent read/write
- Designed for CDC-safe data transfer

### Clock Domains

- **Write clock**: 100 MHz
- **Read clock**: 40 MHz

### Data Transfer Requirement

- Reliable transfer of **9 bytes**
- Direction: **fast domain → slow domain**

### FIFO Depth Notes

- Theoretically required depth ≈ **6 entries**
- Depth 8 caused overflow under simultaneous read/write because:
  - Write speed = **2.5× faster** than read speed
  - Pointer synchronization delay
  - FULL flag asserted too early → potential data loss

**Final FIFO depth = 16 entries**, providing:

- Sufficient safety margin
- No overflow
- Stable and correct FULL/EMPTY logic
- Reliable operation under burst writes
